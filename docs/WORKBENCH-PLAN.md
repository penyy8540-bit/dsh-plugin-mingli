# 命理工作台 · 侧边栏 + 对话 + 每日反馈 · 实施方案 v0.1

> 目标：把现在的「浮窗/页签命盘」升级成**侧边栏常驻的命理工作台**——左边栏一个入口，主区一整页：
> 命主资料、与 DeepSeek 的对话、提问节点历史、每日反馈。
> 本文只做方案与排期，确认后按 P0→P2 实施。

---

## 1. 需求拆解

| # | 需求 | 落点 |
|---|---|---|
| R1 | 插件在**侧边栏**运行 | 左侧栏图标 + 主区独立页面（`sidebar.panellist` + `main`） |
| R2 | **侧边栏里直接对话 DeepSeek** | 插件内自带聊天 UI + 宿主 LLM 流式调用（Typert 流式 RPC） |
| R3 | Agent **看懂宿主资料**再分析 | 每次请求注入「命主上下文块」（四柱/紫微/奇门/轨迹/历史问答摘要） |
| R4 | 有**对话页面**，全部聊天记录，每次提问成一个**节点** | 会话线程 + 提问节点索引（可搜索/收藏/跳回） |
| R5 | 宿主能**快速找到**问过的问题 | 右栏节点列表 + 关键词搜索 + 按命主/标签/时间过滤 |
| R6 | 按**黄历 + 宿主八字**给**每日反馈** | 黄历数据 + 本命合冲 + 规则兜底 + LLM 生成，缓存一天一次 |

## 2. 技术可行性（已实测/已验证，不是猜测）

| 能力 | 结论 | 证据 |
|---|---|---|
| 侧边栏图标 | ✅ `ctx.slots.register({name:'sidebar.panellist', id:'mingli', order, label})` + 图标组件收 `{size, active}` | 官方 `dsh-client-ui-schedule` 就是这样挂「自动化任务」面板 |

| 客户端↔宿主流式 | ✅ Typert 流式 RPC：宿主 service 挂 `typertRemote`，客户端 `remote.$mount(TYPERT_REMOTE)` + `ctx.inject(['remote.mingli'])`，`AsyncIterable` 逐块消费 | `whale-hud` 的 `bridge-contract-source.mjs` / `bridge-client.js` 已跑通 |

## 3. 架构选型

### 3.1 对话后端：三个候选

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 自建对话 + 宿主 LLM RPC（推荐）** | 插件自己渲染聊天；宿主 `ctx.llm.stream` 按「系统提示（含宿主资料）+ 历史消息」调用，流式回传 | 完全可控：自定义 system prompt、上下文裁剪、答案结构；历史节点归插件管；不污染主会话 | 无工具调用（纯推理），需要自己实现 RPC |
| B. 内嵌真实 DSH Session | 插件页里创建/挂载一个真实会话，用官方聊天组件渲染 | 有 Agent + 工具 + skill，能力最强 | 插件页拿不到 session-scoped hooks（`main` 槽不绑 session），要自己造会话 UI；上下文注入别扭；历史节点与 DSH 会话日志两套 |
| **C. A + 一键深挖** | 日常问答走 A；复杂问题点「交给 Harness Agent 深度分析」，带上下文开一个真实会话跳转过去 | 兼顾可控与工具能力 | 多一个跳转入口 |

**推荐：C**（v1 先做 A 的全部能力，C 只做一个按钮：`ctx.uiWorkspace.startSession()` + 预置上下文消息）。

## 5. 上下文注入（R3 的关键）

每次请求组装：

```
[system] 你是命理推演助手。基于给定盘面作答，不得编造盘面；结论标注依据与置信度；
         不做医疗/法律/投资断言；输出 ≤ 300 字，除非用户要求展开。

[system] <HOST_PROFILE>
命主：张三 男 1990-05-15 10:30（真太阳时 -10.7 分）北京
四柱：庚午 辛巳 庚辰 辛巳（日主庚金 中和 57/100）
五行：木4.2% 火29.7% 土23.3% 金40.3% 水2.5%（缺木水）
当前：大运甲申 2017-2026（虚岁28-37）· 2026流年丙午（七杀）
紫微：火六局 · 命宫子破军 · 身宫戌 · 四化 太阳禄/武曲权/太阴科/天同忌
关系：年日戌卯六合；年月戌丑刑；月时丑午害…
今日：丙午日 · 农历九月十八 · 宜… · 忌… · 冲鼠(壬子)煞北 · 值神白虎(黑道)
</HOST_PROFILE>

[user] …（本轮问题）
[assistant] …（历史，最近 6 轮以内）
```

- **token 预算**：上下文块 ≤ 1200 字；历史只带最近 6 轮 + 当前命主的 5 条节点摘要；超限按「轨迹 > 奇门 > 紫微 > 八字」优先级裁剪。
- 问题类型自动识别（事业/财运/感情/健康/择时/合盘/每日）→ 选对应的资料子块，减少无关信息。

## 6. 每日反馈（R6）

**数据**：黄历（lunar-javascript）+ 今日干支 + 本命四柱/日主/流年 + 大运。

**算法（确定性部分，可离线）**：
1. 今日干支 → 与本命年支/日支/月支的合冲刑害破（复现有 `relations` 逻辑）
2. 黄历：宜忌、冲煞、值神吉凶、吉神凶煞、喜/财/福方位、彭祖百忌
3. 用神命中：今日干支五行是否助用神（旺衰法：偏弱→印比；结合调候）
4. 综合 `score 0-100`：基准 50 + 合/助用神 +8~12 − 冲/克用神 −8~12 ± 值神吉凶 ± 宜忌关键词（签约/出行/开市/动土…）
5. 生成模板文案（确定性、无 LLM 也能用）

**LLM 部分**：把上面的结构化结果喂给 LLM，产出 3 段 ≤120 字：
> 今日主题 / 宜做什么 / 一句提醒（含方位或时辰）

**展示**：左侧「今日反馈卡」（日期、干支、分数环、3 段、宜忌 chips、方位）；
主区顶部一条轻量 banner（可关闭）；可选 `workspace.toast` 每天首次打开时提醒。
**缓存**：按 `profileId + date` 缓存；用户点「重新生成」才重跑 LLM。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| Typert 属半公开契约，升级可能变 | 只用 whale-hud 已验证的 stream 描述符形状；版本异常时聊天降级为「复制提示词到主对话」 |
| 上下文超 token | 分块注入 + 预算裁剪 + 问题类型路由（见 §5） |
| LLM 无凭据/额度 | 读取宿主 `llm` 路由状态；失败给明确文案并退回规则文案，不影响盘面功能 |
| 长期历史膨胀 | 节点索引与消息体分离；超过阈值提示导出并归档 |
| 命理内容合规 | 沿用现有红线：不医疗/投资断言、不承诺改运、标注置信度、底部免责声明 |
